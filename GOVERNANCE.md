# Project governance

Solis Tools is maintained in the open. Issues and pull requests are the record
for technical decisions that affect users or contributors.

## Decision making

- Contributors propose changes through an issue or pull request.
- The maintainer considers correctness, safety, compatibility and ongoing
  maintenance cost.
- Discussion should aim for consensus. The lead maintainer makes the final
  decision when consensus cannot be reached.
- Security-sensitive discussions use GitHub's private vulnerability reporting
  instead of public issues.

## Repository policy

- `main` is protected and accepts changes through pull requests.
- Required CI and dependency-review checks must pass before merge.
- Code-owner review is required for changes from contributors.
- Review conversations must be resolved and stale approvals are dismissed when
  a pull request changes.
- Squash merge is the standard merge method and merged branches are deleted.

## Becoming a maintainer

Sustained, constructive contributions may lead to an invitation to become a
maintainer. Maintainers are expected to review changes, support releases,
follow the code of conduct and act in the project's long-term interests.
